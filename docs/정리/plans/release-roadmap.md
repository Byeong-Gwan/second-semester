# 앱 출시 로드맵 (Release Roadmap)

## 현재 상태 (2026-02-03)

### ✅ 완성된 기능
- **학습 관리**: 생성, 삭제, 참여 토글, 진척도 조절
- **타임라인**: 주간 뷰, CRUD, 타입별 색상, 완료 체크
- **할 일 관리**: CRUD, 필터/검색/정렬, 완료율 차트, 우선순위
- **데이터 영속성**: localStorage persist (learnings, timeline, todos)
- **테마**: 다크/라이트 모드, 시스템 설정 자동 감지
- **반응형**: 모바일/태블릿/데스크톱 대응

### 🚧 미완성 기능
- **출석 체크**: 구현 필요
- **진행률 상세**: 차트/통계 구현 필요
- **메인 페이지 카드**: TodoListCard, AttendanceCard 스토어 연동 필요

## 출시 단계별 로드맵

### Phase 1: MVP (Minimum Viable Product) - 2주
**목표**: 핵심 기능만으로 빠르게 출시

#### 필수 작업
- [ ] **출석 체크 기능** (3일)
  - 출석 스토어 생성 (persist)
  - 월별 캘린더 UI
  - 출석 체크/취소
  - 출석률 통계
  
- [ ] **메인 페이지 카드 연동** (2일)
  - TodoListCard를 todos 스토어 연동
  - AttendanceCard를 attendance 스토어 연동
  - MainProgressCard 데이터 계산 로직
  
- [ ] **기본 테스트** (2일)
  - 주요 스토어 단위 테스트
  - 핵심 시나리오 E2E 테스트
  
- [ ] **접근성 개선** (2일)
  - 모달 포커스 트랩
  - 키보드 네비게이션
  - ARIA 속성 추가
  
- [ ] **배포 준비** (2일)
  - Vercel 배포 설정
  - 환경 변수 관리
  - 에러 로깅 (Sentry 등)
  - 성능 최적화 (이미지, 번들 크기)

**예상 기간**: 2주  
**출시 형태**: 베타 버전 (친구/지인 대상)

### Phase 2: 기능 완성 - 1개월
**목표**: 모든 계획된 기능 구현

#### 추가 기능
- [ ] **진행률 상세 페이지** (5일)
  - 학기 진행률 차트

  - 목표 대비 달성률
  
- [ ] **데이터 내보내기/가져오기** (3일)
  - JSON 내보내기
  - JSON 가져오기
  - 데이터 백업 안내
  
- [ ] **알림 기능** (5일)
  - 브라우저 알림 권한
  - 일정 시작 전 알림
  - 할 일 마감일 알림
  
- [ ] **검색 기능** (3일)
  - 전역 검색 (학습/일정/할 일)
  - 검색 결과 하이라이트
  
- [ ] **필터/정렬 고도화** (3일)
  - 복합 필터 (AND/OR)
  - 커스텀 정렬 순서 저장
  
- [ ] **다국어 지원** (선택, 5일)
  - 영어 번역

**예상 기간**: 1개월  
**출시 형태**: 정식 버전 1.0

## 출시 시기 추천

### 옵션 A: 빠른 출시 (2주 후)
**장점**:
- 빠른 사용자 피드백
- 시장 검증 가능
- 개발 동기 유지

**단점**:
- 기능 부족
- 버그 가능성
- 첫인상 리스크

**추천 대상**: 
- 빠른 검증이 필요한 경우
- 소규모 사용자 대상 (친구/지인)
- 베타 테스터 모집 목적

### 옵션 B: 안정적 출시 (1~2개월 후)
**장점**:
- 완성도 높은 제품
- 버그 최소화
- 좋은 첫인상

**단점**:
- 출시 지연
- 완벽주의 함정
- 개발 피로도

**추천 대상**:
- 공개 출시 목표
- 포트폴리오 용도
- 정식 서비스 런칭

### 옵션 C: 단계적 출시 (추천)
**1단계 (2주)**: 베타 버전 - 친구/지인 대상
- 핵심 기능만 구현
- 피드백 수집
- 버그 수정

**2단계 (1개월)**: 정식 버전 - 제한적 공개
- 모든 기능 완성
- 안정성 확보
- 소규모 마케팅

**3단계 (2개월)**: 확장 버전 - 전면 공개
- 고급 기능 추가
- 대규모 마케팅
- 커뮤니티 구축

## 리스크 관리

### 기술적 리스크
- **localStorage 용량 제한**: IndexedDB로 마이그레이션 계획
- **브라우저 호환성**: Polyfill 준비
- **성능 저하**: 코드 스플리팅, 레이지 로딩

### 사용자 리스크
- **데이터 손실**: 백업 기능 필수
- **학습 곡선**: 온보딩 튜토리얼
- **이탈률**: 푸시 알림, 이메일 리마인더

### 운영 리스크
- **서버 비용**: Vercel 무료 플랜 한도 모니터링
- **유지보수 부담**: 자동화, 모니터링 도구 활용
- **법적 이슈**: 개인정보 처리방침 준수

## 결론 및 추천

### 현재 상태 평가
- **완성도**: 약 70% (핵심 기능 완성)
- **안정성**: 중간 (테스트 부족)
- **사용자 경험**: 양호 (UI/UX 준수)

### 추천 출시 시기
**2주 후 베타 출시 → 1개월 후 정식 출시**

### 이유
1. **핵심 기능 완성**: 학습, 타임라인, 할 일 모두 동작
2. **빠른 검증**: 실제 사용자 피드백 필요
3. **동기 유지**: 완벽주의 함정 회피
4. **단계적 개선**: 피드백 기반 개선 가능

### 다음 2주 집중 작업
1. 출석 기능 구현 (3일)
2. 메인 페이지 카드 연동 (2일)
3. 기본 테스트 (2일)
4. 접근성 개선 (2일)
5. 배포 준비 (2일)
6. 베타 출시 (1일)
