## 1️⃣ 출석 관리 기능 (기존 확인)

### 📁 파일: `lib/store/attendance.ts`

#### 왜 만들었나?
- README에 명시된 핵심 기능 중 하나
- 학습 관리 시스템에서 출석 체크는 필수 기능
- 결석 횟수 관리 및 출석률 추적 필요

#### 주요 인터페이스

```typescript
export interface AttendanceRecord {
  date: string;        // yyyy-MM-dd 형식
  status: "present" | "absent" | "late";  // 출석/결석/지각
}
```

**왜 이렇게 설계했나?**
- `date`: 문자열로 저장하여 비교 및 필터링 용이
- `status`: 3가지 상태로 명확히 구분
- 간단한 구조로 localStorage 저장 최적화

#### 주요 함수들

##### 1. `markAttendance(date, status)`
```typescript
markAttendance: (date: string, status: "present" | "absent" | "late") => {
  set((s) => {
    const existing = s.records.find((r) => r.date === date);
    if (existing) {
      // 기존 기록 업데이트
      return { records: s.records.map((r) => (r.date === date ? { ...r, status } : r)) };
    }
    // 새 기록 추가
    return { records: [...s.records, { date, status }] };
  });
}
```

**왜 이렇게 구현했나?**
- 같은 날짜에 중복 기록 방지
- 기존 기록이 있으면 업데이트, 없으면 추가
- 불변성 유지 (map으로 새 배열 생성)

##### 2. `getUsedAbsences()`
```typescript
getUsedAbsences: () => {
  return get().records.filter((r) => r.status === "absent").length;
}
```

**왜 필요한가?**
- 결석 횟수 제한 관리 (예: 5회 초과 시 경고)
- 남은 결석 횟수 계산에 사용

##### 3. `getAttendanceRate()`
```typescript
getAttendanceRate: () => {
  const records = get().records;
  if (records.length === 0) return 100;
  const present = records.filter((r) => r.status === "present").length;
  return Math.round((present / records.length) * 100);
}
```

**왜 이렇게 계산하나?**
- 기록이 없으면 100% 반환 (초기 상태)
- 출석만 카운트 (지각은 출석률에서 제외)
- 반올림하여 정수로 표시

##### 4. `getMonthRecords(year, month)`
```typescript
getMonthRecords: (year: number, month: number) => {
  const prefix = `${year}-${String(month).padStart(2, "0")}`;
  return get().records.filter((r) => r.date.startsWith(prefix));
}
```

**왜 필요한가?**
- 월별 출석 현황 조회
- 달력 뷰에서 해당 월의 기록만 표시
- 문자열 prefix 매칭으로 간단하게 구현

## 2️⃣ 데이터 백업/복구 시스템

### 📁 파일: `lib/utils/backup.ts`

#### 왜 만들었나?
**문제점**:
- 현재 모든 데이터가 localStorage에만 저장
- 브라우저 캐시 삭제 시 **모든 데이터 손실**
- 기기 간 데이터 이동 불가능

**해결책**:
- JSON 파일로 백업/복구 기능 제공
- 사용자가 직접 데이터 관리 가능
- 정기적인 백업으로 데이터 안전성 확보

#### 주요 인터페이스

```typescript
export interface BackupData {
  version: string;      // 백업 파일 버전
  timestamp: string;    // 백업 생성 시간
  data: {
    learnings: any;     // 학습 데이터
    todos: any;         // 할 일 데이터
    attendance: any;    // 출석 데이터
  };
}
```

**왜 이렇게 설계했나?**
- `version`: 향후 백업 형식 변경 시 호환성 체크
- `timestamp`: 백업 생성 시간 기록으로 최신 백업 식별
- `data`: 모든 스토어 데이터를 하나의 객체로 묶음

#### 주요 함수들

##### 1. `exportData()`
```typescript
export const exportData = (): BackupData => {
  const learnings = useLearningStore.getState();
  const todos = useTodoStore.getState();
  const attendance = useAttendanceStore.getState();

  return {
    version: "1.0.0",
    timestamp: new Date().toISOString(),
    data: {
      learnings: { learnings: learnings.learnings },
      todos: { todos: todos.todos },
      attendance: {
        records: attendance.records,
        allowedAbsences: attendance.allowedAbsences,
      },
    },
  };
};
```

**왜 이렇게 구현했나?**
- 각 스토어의 현재 상태를 가져옴
- 필요한 데이터만 선택적으로 추출 (함수는 제외)
- ISO 형식 타임스탬프로 정확한 시간 기록

**왜 함수를 제외하나?**
- JSON은 함수를 직렬화할 수 없음
- 데이터만 백업하고 로직은 코드에 유지

##### 2. `downloadBackup()`
```typescript
export const downloadBackup = () => {
  const backup = exportData();
  const blob = new Blob([JSON.stringify(backup, null, 2)], { type: "application/json" });
  const url = URL.createObjectURL(blob);
  const a = document.createElement("a");
  a.href = url;
  a.download = `second-semester-backup-${new Date().toISOString().split("T")[0]}.json`;
  document.body.appendChild(a);
  a.click();
  document.body.removeChild(a);
  URL.revokeObjectURL(url);
};
```

**왜 이렇게 구현했나?**
- `Blob`: JSON 데이터를 파일로 변환
- `JSON.stringify(backup, null, 2)`: 가독성 좋게 포맷팅 (들여쓰기 2칸)
- `URL.createObjectURL`: 브라우저 메모리에 임시 URL 생성
- `a.click()`: 프로그래밍 방식으로 다운로드 트리거
- `URL.revokeObjectURL`: 메모리 누수 방지

**파일명 형식**:
- `second-semester-backup-2026-02-06.json`
- 날짜 포함으로 여러 백업 구분 가능

##### 3. `importData(backupData)`
```typescript
export const importData = (backupData: BackupData): { success: boolean; error?: string } => {
  try {
    // 버전 체크
    if (!backupData.version) {
      return { success: false, error: "잘못된 백업 파일 형식입니다." };
    }

    // 데이터 복구
    if (backupData.data.learnings?.learnings) {
      useLearningStore.setState({ learnings: backupData.data.learnings.learnings });
    }
    if (backupData.data.todos?.todos) {
      useTodoStore.setState({ todos: backupData.data.todos.todos });
    }
    if (backupData.data.attendance) {
      const updates: any = {};
      if (backupData.data.attendance.records) {
        updates.records = backupData.data.attendance.records;
      }
      if (backupData.data.attendance.allowedAbsences !== undefined) {
        updates.allowedAbsences = backupData.data.attendance.allowedAbsences;
      }
      useAttendanceStore.setState(updates);
    }

    return { success: true };
  } catch (error) {
    return { success: false, error: "데이터 복구 중 오류가 발생했습니다." };
  }
};
```

**왜 이렇게 구현했나?**
- **버전 체크**: 잘못된 파일 형식 방지
- **옵셔널 체이닝 (`?.`)**: 데이터가 없어도 에러 방지
- **부분 복구**: 일부 데이터만 있어도 복구 가능
- **에러 처리**: try-catch로 안전하게 처리
- **명확한 반환값**: success/error로 결과 전달

##### 4. `uploadBackup(file)`
```typescript
export const uploadBackup = (file: File): Promise<{ success: boolean; error?: string }> => {
  return new Promise((resolve) => {
    const reader = new FileReader();
    
    reader.onload = (e) => {
      try {
        const content = e.target?.result as string;
        const backupData: BackupData = JSON.parse(content);
        const result = importData(backupData);
        resolve(result);
      } catch (error) {
        resolve({ success: false, error: "파일을 읽을 수 없습니다." });
      }
    };

    reader.onerror = () => {
      resolve({ success: false, error: "파일 읽기 중 오류가 발생했습니다." });
    };

    reader.readAsText(file);
  });
};
```

**왜 Promise를 사용하나?**
- `FileReader`는 비동기 API
- async/await 패턴으로 사용하기 위해 Promise로 래핑

**왜 reject 대신 resolve를 사용하나?**
- 파일 읽기 실패도 정상적인 흐름으로 처리
- 에러 메시지를 사용자에게 표시하기 위함

## 3️⃣ 에러 처리 시스템

### 📁 파일: `components/ui/toast.tsx`

#### 왜 만들었나?
**문제점**:
- 기존에는 인라인 상태 메시지만 사용
- 페이지마다 중복 코드 발생
- 일관성 없는 알림 디자인

**해결책**:
- 전역 Toast 시스템 구현
- Context API로 어디서든 사용 가능
- 자동 사라짐 기능

#### 주요 인터페이스

```typescript
export interface ToastProps {
  id: string;
  title?: string;
  description?: string;
  variant?: "default" | "success" | "error" | "warning";
  duration?: number;
}
```

**왜 이렇게 설계했나?**
- `id`: 각 Toast를 고유하게 식별
- `title/description`: 제목과 상세 내용 분리
- `variant`: 4가지 타입으로 시각적 구분
- `duration`: 표시 시간 커스터마이징 (기본 3초)

#### 주요 함수들

##### 1. `addToast(toast)`
```typescript
const addToast = React.useCallback((toast: Omit<ToastProps, "id">) => {
  const id = Math.random().toString(36).slice(2);
  const newToast = { ...toast, id };
  setToasts((prev) => [...prev, newToast]);

  const duration = toast.duration || 3000;
  setTimeout(() => {
    removeToast(id);
  }, duration);
}, []);
```

**왜 useCallback을 사용하나?**
- 함수 재생성 방지
- Context 값이 변경될 때마다 모든 컴포넌트가 리렌더링되는 것 방지

**왜 자동으로 ID를 생성하나?**
- 사용자가 ID를 신경 쓰지 않아도 됨
- 고유성 보장

**왜 setTimeout을 사용하나?**
- 지정된 시간 후 자동으로 Toast 제거
- 사용자가 수동으로 닫지 않아도 됨

##### 2. `removeToast(id)`
```typescript
const removeToast = React.useCallback((id: string) => {
  setToasts((prev) => prev.filter((t) => t.id !== id));
}, []);
```

**왜 filter를 사용하나?**
- 불변성 유지
- 해당 ID의 Toast만 제거

### 📁 파일: `components/error-boundary.tsx`

#### 왜 만들었나?
**문제점**:
- React 컴포넌트 에러 발생 시 전체 앱이 크래시
- 사용자에게 빈 화면만 표시
- 에러 원인 파악 어려움

**해결책**:
- ErrorBoundary로 에러 캐치
- 사용자 친화적인 에러 화면 표시
- 페이지 새로고침으로 복구 가능

#### 클래스 컴포넌트를 사용하는 이유

```typescript
export class ErrorBoundary extends React.Component<ErrorBoundaryProps, ErrorBoundaryState> {
  static getDerivedStateFromError(error: Error): ErrorBoundaryState {
    return { hasError: true, error };
  }

  componentDidCatch(error: Error, errorInfo: React.ErrorInfo) {
    console.error("ErrorBoundary caught an error:", error, errorInfo);
  }
}
```

**왜 클래스 컴포넌트를 사용하나?**
- React의 ErrorBoundary는 클래스 컴포넌트만 지원
- `getDerivedStateFromError`와 `componentDidCatch`는 클래스 메서드

**왜 두 개의 메서드가 필요한가?**
- `getDerivedStateFromError`: 에러 발생 시 상태 업데이트 (렌더링 단계)
- `componentDidCatch`: 에러 로깅 (커밋 단계)

#### 에러 UI

```typescript
if (this.state.hasError) {

```

**왜 이렇게 디자인했나?**
- 중앙 정렬로 에러에 집중
- 에러 메시지 명확히 표시
- 새로고침 버튼으로 복구 방법 제공

## 📊 전체 아키텍처

### 데이터 흐름

```
사용자 액션
    ↓
설정 페이지 (handleDownload/handleUpload)
    ↓
백업 유틸리티 (exportData/importData)
    ↓
Zustand 스토어 (learnings/todos/attendance)
    ↓
localStorage (persist middleware)
```

### 에러 처리 흐름

```
컴포넌트 에러 발생
    ↓
```
