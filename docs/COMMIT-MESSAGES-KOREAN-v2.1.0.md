## 💡 커밋 메시지 가이드라인 (한글)

### 커밋 메시지 구조
```
<타입>(<범위>): <제목>

<본문>

<꼬리말>
```

### 타입 (Type)
- `feat`: 새로운 기능
- `fix`: 버그 수정
- `docs`: 문서 변경
- `style`: 코드 포맷팅, 세미콜론 누락 등
- `refactor`: 코드 리팩토링
- `perf`: 성능 개선
- `test`: 테스트 추가/수정
- `chore`: 빌드/유틸리티 변경

### 범위 (Scope)
- `nav`: 네비게이션 관련
- `main`: 메인 페이지
- `activity`: 활동 페이지
- `crud`: CRUD 기능
- `news`: 뉴스 시스템
- `daily`: 일상 페이지
- `settings`: 설정 페이지
- `mobile`: 모바일 최적화
- `api`: API 관련
- `store`: 상태 관리
- `ui`: UI 컴포넌트
- `perf`: 성능 관련

### 제목 (Subject)
- 50자 이내로 작성
- 대문자로 시작
- 마침표(.) 없이 끝
- 과거형이 아닌 명령형으로 작성 ("수정됨"이 아닌 "수정")

### 본문 (Body)
- 어떻게가 아닌 무엇을, 왜 변경했는지 설명
- 72자 줄 바꿈 준수

### 꼬리말 (Footer)
- 주요 변경사항: "주요 변경사항:"
- 이슈 참조: "해결 #123"
